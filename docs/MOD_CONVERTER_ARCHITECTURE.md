# Mod Converter and Compatibility Architecture

## Current implementation (repository audit)

The repository already contains a partial, native mod profile system. This is an audit of code present at the time of implementation, not a compatibility claim for arbitrary community mods.

| Area | Existing implementation | Limits and integration point |
| --- | --- | --- |
| Android launcher and game startup | `android/app/src/main/java/org/ra2/engine/SetupActivity.java` offers the “Mods & compatibility” entry and SAF folder selection. `ModManager.java` imports into app-managed `Android/data/.../files/ra2/mods/` and stores the opt-in profile ID in SharedPreferences. `RA2Activity.java` passes its canonical path as `RA2_MOD_DIR` before SDL/native initialization. | This process restart boundary is the correct place to change profiles. The match cannot change its mod after startup. |
| Native engine and JNI | C++17 engine is `engine/main.cpp` and `engine/mod_android.cpp`; JNI exposes a read-only native report. The Java launcher loads `libSDL2` and `libmain` to inspect profiles. Shared source lists are in `cmake/ra2_sources.cmake`. | No separate app or new runtime is needed. |
| MIX and loose resources | `src/mix.cpp` reads MIX archives. `src/asset_fs.cpp` implements original base archive search and gives the active profile first lookup priority. `src/mod_profile.cpp` indexes loose files and flat-root mod MIX archives, with loose resources ahead of archives. | Mod archive priority is currently deterministic by descending filename; nested MIX support is limited to selected YR child archives. The complete original archive ordering is not emulated for arbitrary mod archives. |
| INI parsing and merge | `src/ini.cpp` provides case-insensitive sections/keys, preserves duplicate rows and returns the last duplicate on lookup. `merge_mod_ini` overlays patch keys while preserving base registry order. `engine/main.cpp::read_ra2md_file` merges active loose/MIX `rulesmd.ini` and other requested YR INIs before callers parse them. | Only files already requested by the engine can affect execution. List/registry semantics need per-section validation; no general INI compiler or unknown-key execution exists. Current inspected config names include `rulesmd.ini`, `artmd.ini`, `aimd.ini`, `soundmd.ini`, and `evamd.ini`. |
| Asset decoders | `src/shp.cpp`, `src/vxl.cpp`, `src/hva.cpp`, `src/theater.cpp`, audio decoders and `src/map.cpp` handle supported base formats. The mod profile exposes supported resource reads to existing asset paths. | Decoder support does not imply all loading paths accept mod resources. Custom TMP theater templates and several audio/string-bank paths remain incomplete and are reported by the analyzer. |
| Mod analyzer and safety | `ModProfile::inspect` in `src/mod_profile.cpp` rejects missing/invalid manifests, unsafe symlinks, excessive depth/count, malformed root MIX archives, extension properties, and selected unsupported resources; computes FNV-1a over file names and bytes; returns `SUPPORTED`, `PARTIAL`, or `BLOCKED`. | The analyzer recognizes a limited, initial key subset. Partial means unknown/unverified properties may exist; it is not a runtime compatibility result. ZIP import is handled on Android and never runs imported content. The scanner now blocks Windows executable/script extensions at any depth. |
| Activation, saves, multiplayer | `engine/main.cpp` inspects and activates the selected profile before entering the game, records a report, and isolates save preferences by mod ID and content fingerprint. `engine/mp_pages.inc` includes effective INI bytes in existing data compatibility checks. | Modded multiplayer is not certified for deterministic synchronization; save isolation is not yet an explicit embedded save header. Keep compatibility warning visible and avoid claims of cross-build mod multiplayer. |
| Tests | `tests/test_mod_profile.cpp` covers profile safety, hashes, overlay reads, merge order, activation/deactivation and map gating. | No Android SAF/ZIP instrumentation tests exist in this environment. No retail assets are committed for mod tests. |

## First milestone delivered

1. Keep SAF folder import and add SAF ZIP document selection in the existing launcher.
2. Extract ZIP entries on a background thread into a temporary app-private directory, then atomically rename on success. Reject absolute paths, drive paths, `..`, duplicate case-insensitive paths, excessive nesting, over 16,384 entries, over 2 GiB per file, and over 8 GiB expanded total. ZIP entries are written as ordinary data files; archive permissions are not applied and nothing is executed. A single enclosing directory is flattened to make common mod ZIP layouts analyzable.
3. If the imported copy lacks `mod.ini`, generate a local `Requires=base` manifest so the existing analyzer can decide eligibility. The user’s selected source folder/archive is never modified. Imported DLL/EXE/script files are reported as blocking at any directory depth.
4. The existing native path merges supported `rulesmd.ini` overrides before `Rules` initialization. The native regression fixture now confirms MTNK cost, strength and speed overrides survive parse/merge into the engine’s current `Rules` model. This is the initial gameplay-bearing vertical slice; it is not a general compiled representation or a runtime test of a retail match.

## Compatibility contract and next milestones

- `SUPPORTED` currently means the profile passed the implemented structural and key checks. It does not mean gameplay compatibility was verified. Runtime gameplay status must remain “not verified” until a representative match/campaign check exists.
- First priority after this milestone: bounded, versioned compiled-config cache keyed by actual source bytes, base config bytes, compiler version and capability version; atomic writes and cache corruption recovery.
- Next: turn the current key allowlist into a documented capability registry tied to the fields actually consumed by the engine; validate referenced units/assets and RA2 versus Yuri’s Revenge requirements.
- Then add reports for feature families, configuration provenance and unsupported Ares/Phobos extensions. DLL injection features cannot be supplied by loading their INIs; Ares/Phobos DLLs are Windows code and are not executed.
- Extend Android tests for safe ZIP extraction, path traversal, malformed/encrypted archives, cancellation and size limits. Native tests continue to cover parsing, merge, profile activation and resource precedence.
- Do not advertise Mental Omega, Rise of the East, Ares, Phobos, or broad mod compatibility until their actual feature dependencies are implemented and exercised.
